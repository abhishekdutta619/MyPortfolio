"Scalable" shows up on nearly every front-end résumé, including the one behind this site. It's also one of the vaguest words in the industry — for a back-end system it at least gestures at load and throughput, but a landing page doesn't have "load" in that sense. So what is it actually supposed to mean here?

A more useful definition, for front-end work specifically: **a scalable codebase is one where the cost of the next change doesn't grow with the size of the codebase.**

That reframes it as an engineering-process property, not a performance one — and it's testable in ways "handles traffic" isn't.

## Three places this actually shows up

**Component boundaries.** If adding a new field to a form means touching six files that all quietly assume the old shape, that's not scalable — regardless of how fast the page loads. A well-drawn boundary means the next feature is additive, not archaeological.

**Design tokens over hardcoded values.** This site's own Tailwind config is a small example: colors, spacing, and type scale live in one place. Changing the accent color site-wide is a one-line edit, not a find-and-replace across forty components. That's the entire point of a token system — it's not about looking consistent, it's about the *cost of changing your mind* staying low.

**State that doesn't leak.** The publish-pipeline demo on the [Simply Dwell Design case study](/#projects) keeps its stage index and running flag local to one component instead of threading them through global state or prop-drilling them three levels deep. Small example, same principle: state should live as close as possible to where it's used, so a change in one part of the UI doesn't require understanding five other parts to reason about safely.

## The honest failure mode

None of this is free. Over-abstracting *too* early — building a generic system for a problem you don't have yet — is its own kind of unscalable, because now every change has to go through an abstraction that doesn't quite fit. I've shipped that mistake before. The skill isn't "always abstract" or "never abstract" — it's noticing when a pattern has actually repeated three times, not assuming on the first occurrence that it will.

"Scalable" is a claim about the future, made by someone who doesn't get to see it. The only way to make it honest is to make it concrete enough that someone else could check.
